## Што оди каде — прво ова, за да нема забуна

Продукцијата на MathDigitizer е **на две места**, не на едно. Ова се гледа од
одговорот на серверот, не од претпоставка:

| Дел | Домен | Server header | Како се ажурира |
|---|---|---|---|
| **Фронтенд** | `math.mismath.net` | `hcdn` (Hostinger) | `deploy.yml`, FTP, при push на `main` |
| **API + Firebase auth** | `mathdigitizer.vercel.app` | `Vercel` | Vercel сам, при push на `main` |
| AI Navigator | `ai.mismath.net` | — | **друго репо, не се допира** |

`math.mismath.net` **не е CNAME кон Vercel** — резолвира на 92.113.16.58
(Hostinger). А `mathdigitizer.vercel.app` враќа само `ok`, зашто `vercel.json`
намерно гради празен `public/`:

```json
"buildCommand": "mkdir -p public && echo ok > public/index.html"
```

Vercel не го служи интерфејсот. Тој постои за API рутите (`/api/scrape`,
`/api/ingestion/*`, `/api/youtube/*`) и за Firebase auth handler-от преку
rewrite — затоа `authDomain` во `firebase-applet-config.json` е
`mathdigitizer.vercel.app`. Најавата со Google минува оттаму.

**Затоа еден merge активира две распоредувања.** За ова издание тоа е безбедно:
`git diff ec00069..HEAD -- api/ server.ts vercel.json` е празен, па Vercel ќе
изгради точно она што е горе сега. Ризикот е само на фронтендот, кој има вградена
верификација и рачна резерва.

`deploy.yml` пишува исклучиво во `domains/mismath.net/public_html/math`. Нема
начин ова издание да го допре `ai.mismath.net` — тој се распоредува од друго
репо, со свои тајни и свој workflow.

**Состојба пред распоредувањето:** продукцијата вртка `ec00069` од 6.08.2026.
Живиот bundle нема `curriculum-data` chunk, што е доказ дека фаза 9.2 не е таму.

## Блокер: правилата не се распоредуваат од CI

`deploy.yml` качува само `dist/`. `firestore.rules` мора да се распореди одделно:

```bash
npx firebase-tools deploy --only firestore:rules --project mathdigitizer-pro
```

**Ако кодот слета без правилата**, двете нови функционалности ќе се појават во
навигацијата и ќе паднат при секое пишување. Нема catch-all правило во
`firestore.rules`, па стандардот е одбивање — тоа е безбедно, но скршено:
наставникот гледа копче што не работи.

**Затоа правилата одат ПРВИ.** Тие се додатни за постоечките колекции, па
распоредени пред кодот не менуваат ништо за тековните корисници.

### Сметката најавена локално нема пристап до продукцискиот проект

Firebase CLI тука е најавен со сметка што гледа четири проекти —
`ai-navigator-ee967`, `math-ai-navigator-370399-9e123`,
`math-curriculum-navigato-1a9e9`, `mathgenius-adaptive-learning` — а
продукцијата вртка на **`mathdigitizer-pro`** (`firebase-applet-config.json`),
кој не е меѓу нив:

```
Error: Request to .../projects/mathdigitizer-pro/databases had HTTP Error: 403,
The caller does not have permission
```

Трите „navigator" проекти се на `ai.mismath.net`. Значи `mathdigitizer-pro` е под
друга Google сметка. Пред распоредувањето:

```bash
npx firebase-tools login          # сметката што го поседува mathdigitizer-pro
npx firebase-tools projects:list  # мора да го покаже во листата
```

Ако не се појави ни тогаш, се проверува IAM улогата на таа сметка во
Firebase Console → Project settings → Users and permissions. За распоредување
правила треба најмалку **Firebase Rules Admin**.

## Единствената промена врз постоечка колекција

`summative_attempts` сега бара испитот да е отворен при предавање
(фаза 5.3, `examIsOpen`). Проверено дека е безбедно за постоечките испити:

- `status: 'open' | 'closed'` **веќе постоеше** во `ec00069`, па секој испит во
  продукција го носи;
- `opens_at` / `due_at` ги воведе токму ова издание, па ниту еден постоечки испит
  ги нема — а правилото има гранка за отсутни полиња
  (`!('opens_at' in exam)`), која поминува.

Значи затегнувањето не може да блокира предавање на испит што веќе постои.
Ако сепак се појави пријава, првото што се проверува е дали тој испит има
`status == 'open'`.

## Редослед

1. **Правила прво.** `firebase login` со точната сметка, потоа
   `deploy --only firestore:rules --project mathdigitizer-pro`. Додатни се,
   не менуваат ништо додека кодот не слета.
2. **PR наместо директен merge.** `quality-gates.yml` трча на pull request и
   поминува низ целиот сет пред cPanel да биде допрен. Троши квота — за 51 комит
   пред почеток на учебна година вреди.
3. **Merge во `main`** го активира `deploy.yml`.
4. **Верификација** е вградена: workflow-от го споредува живиот bundle со
   изградениот, шест обиди во ~60 секунди, и паѓа гласно ако не се совпаднат.
   Не може лажно да пријави успех.

Најчестото паѓање не е кодот. Run-от од 6.08.2026 22:05 падна со
`cd: Fatal error: max-retries exceeded (Connection timed out)` — Hostinger FTP
истече. Workflow-от оттогаш има три обиди со пауза и лимит од 30 минути, а
следниот run истиот ден помина. **Прво повторно пуштање.**

### Рачна резерва (потврдена)

Ако FTP продолжи да паѓа, cPanel File Manager оди преку HTTPS и го заобиколува
целото FTP ограничување:

```bash
npm run build
cd dist && zip -r ../MathDigitizer-deploy.zip .
```

cPanel → File Manager → `public_html/math/` → испразни → Upload zip → Extract.
Дозволите се 644 автоматски. Околу пет минути.

### Враќање назад

Bundle-имињата носат хеш од содржината, па враќањето значи повторно
распоредување на претходниот комит на `main`:

```bash
git checkout ec00069 && npm run build   # или Re-run на успешниот run од 6.08
```

Правилата се враќаат преку Firebase Console → Firestore → Rules → историја на
верзии.

## Што нема да работи веднаш по распоредувањето

Ништо не е скршено, но вреди да се знае:

- **Учебници** (`/textbooks`) бара `knowledge_skills` правила и Gemini квота.
  Секое поглавје е еден повик; учебник од 40 поглавја се 40 повици.
- **Концепт-мапи** (`/mind-maps`) бара `concept_maps` правила.
- Дневникот сега запишува оценка **само** за ученик избран од паралелка.
  Наставник што досега пишувал име ќе добие аналитика без оценка, со објаснување
  на екранот. Тоа е намерно (наод Н-3), но е промена во навиката.
